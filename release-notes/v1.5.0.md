# Aura Store 1.5.0

A source tab no longer stops at the rows the site chose to feature, and the store now offers its own
update from inside itself.

- Under a source's front page is everything else that source lists, newest first, filling in a page
  at a time as you scroll. The walk uses each site's own listing: 9MOD's posts route, 5play's games
  and apps listings, GetModsAPK's sitemap, AN1's 281-page games catalogue, ApkVision's update log.
  A source tab is now every app the source has, not the shelves it opened on.
- A newer Aura Store release raises a banner under the brand bar, carrying the version and the size.
  It is there from the check, not from the next launch, and it stays after the dialog's *Later*. A
  tap reopens the offer without asking GitHub again. *Later* on the banner hides it until the app is
  started again; nothing is written down, so the update is never lost to a dismissal.
- The store's own download now shows its progress above the release notes: a bar, the percentage and
  the byte count. The notes scroll under it. Before this the bar sat at the bottom of the notes,
  which is below the fold on any release body worth reading, so a download that worked looked like a
  button that did nothing.

## The version

The version is 1.5.0 and the version code is 10500. The application id and the signing key are
unchanged, so this release updates an installed copy in place and keeps its data.

## Two builds

- `Aura-Store-v1.5.0.apk` is the build to install. It is signed with the project key, updates an
  installed copy in place, and is 2.39 MB.
- `Aura-Store-v1.5.0-debug.apk` is the debug build: 14.42 MB, debug-signed, with the full symbol
  set and no shrinking. It cannot replace or update a release install, and Android will refuse it
  over one. It is here for testing a change against a build that keeps every name.

Each file has a `.sha256` beside it. Compare with `sha256sum`, or with `Get-FileHash` on Windows.
