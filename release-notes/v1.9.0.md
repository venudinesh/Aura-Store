# Aura Store 1.9.0

Every file APKPorts publishes now has a working link, and the store offers its own updates in the
app.

## APKPorts shows every file

A game page's download buttons are read in full. Google Drive links are followed to the address that
serves the bytes, and Yandex Disk links through the public-resource API, so both download inside the
store. Vexfile, Gofile and ModsFire wrap their files in a page only a browser can finish, so their
rows now keep the real link and open it in the browser instead of being hidden. A ROMFS archive is
named as one, not as a zip.

A page whose unlock fails no longer looks empty: the buttons remain, marked for the browser.

## The update card

A new release opens a card with the app's mark, the version, the two build pills and the notes. One
full-width action starts the download, the hash is checked, and the system installer opens. The
banner stays on the first screen until the release is installed.

The offer starts on the build this copy can replace. A stored preference for the debug build no
longer turns a release update into *Save APK* by accident; picking the other build still saves it
and says so.

## The version

The version is 1.9.0 and the version code is 10900. The application id and the signing key are
unchanged, so a 1.8.x install updates in place.

## Two builds

- `Aura-Store-v1.9.0.apk` is the signed release build.
- `Aura-Store-v1.9.0-debug.apk` is the debug build: debug-signed, unshrunk, and not installable over
  a release copy.

Each file has a `.sha256` beside it. Compare with `sha256sum`, or with `Get-FileHash` on Windows.
