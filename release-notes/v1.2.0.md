# Aura Store 1.2.0

A tab per server, new and updated first, and a store that keeps itself current.

- Browse carries a tab for each catalogue you have switched on. The catalogue tab keeps the
  LiteAPKs feed; every other tab carries that catalogue's own categories and its apps a page at a
  time, so the list reaches what the website lists rather than its first screen.
- New and updated comes first. *Top charts* and *Trending* sit behind it.
- An app updated through the store leaves the You tab's update list as soon as the install lands,
  and stays gone after a tab switch or a cold start.

## The store updates itself

Settings shows the installed version and its code on a row of its own, with the check's state and
*Check now* on the row below. When GitHub carries a newer release, the offer appears with its
notes; the download comes from the release page, is checked against the SHA-256 GitHub publishes
for the file, and then opens Android's installer. A debug install takes the debug APK and a release
install the signed one, because Android will not let one signing key replace the other.

The version name is `MAJOR.MINOR.PATCH` and the version code is derived from it, `major × 10 000 +
minor × 100 + patch`, so this build is 10200. The two cannot disagree.

This release updates 1.1.0 in place: same application id, same signing key, and a higher code, so
Android takes it over and keeps the data.

## Two builds

- `Aura-Store-v1.2.0.apk` is the build to install. It is signed with the project key, updates an
  installed copy in place, and is 2.49 MB.
- `Aura-Store-v1.2.0-debug.apk` is the debug build: 15.08 MB, debug-signed, with the full symbol
  set and no shrinking. It cannot replace or update a release install, and Android will refuse it
  over one. It is here for testing a change against a build that keeps every name.

Each file has a `.sha256` beside it. Compare with `sha256sum`, or with `Get-FileHash` on Windows.
