# Aura Store 1.4.0

The update notification now says which app it is talking about.

- One card per app with a newer build, each wearing that app's own icon and carrying its name.
- The card prints the version pair, `v1.2.3 → v1.4.0`, so the change is visible without opening the
  store.
- The cards are not grouped. A group folds into a single summary and shows one icon for all of them,
  which is the thing this notification exists to avoid.
- The first card in a batch may sound once; the rest land quietly, so six updates are six readable
  cards and one chime.
- A card leaves when its update does. The apps reported by the last check are remembered, and the
  next check cancels any card whose app it did not report again.
- The You tab row and the notification now format the pair from the same function, so they cannot
  drift apart.

## The version

The version is 1.4.0 and the version code is 10400. The application id and the signing key are
unchanged, so this release updates an installed copy in place and keeps its data.

## Two builds

- `Aura-Store-v1.4.0.apk` is the build to install. It is signed with the project key, updates an
  installed copy in place, and is 2.38 MB.
- `Aura-Store-v1.4.0-debug.apk` is the debug build: 14.40 MB, debug-signed, with the full symbol
  set and no shrinking. It cannot replace or update a release install, and Android will refuse it
  over one. It is here for testing a change against a build that keeps every name.

Each file has a `.sha256` beside it. Compare with `sha256sum`, or with `Get-FileHash` on Windows.
